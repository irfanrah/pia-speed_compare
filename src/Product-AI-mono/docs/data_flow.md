## 2. 데이터 흐름 상세

### 2.1 입력 단계: API 요청 → 파라미터 파싱

```
Backend Server
    │
    │  POST /api/v1/stream/add
    │  {
    │    "cameraId": 1,
    │    "cameraUrl": "rtsp://...",
    │    "organization": "customer_name",
    │    "cvEvent":  [{ "name": "helmet_cv", "roi": {...}, ... }],
    │    "retEvent": [{ "name": "폭력_ret", "abnormalText": "...", ... }],
    │    "vqaEvent": [{ "name": "낙상_vqa", "roi": {...}, ... }]
    │  }
    │
    ▼
AddStreamModel (DTO/stream_params.py)
    │
    │  name 필드 기반으로 올바른 Pydantic 모델로 자동 라우팅
    │  ┌─────────────────────────────────────────────────────────────┐
    │  │ cvEvent 파싱 (parse_cv_events):                            │
    │  │   "helmet_cv"      → HelmetModel (CategoryBase)            │
    │  │   "배회_cv"         → LoiteringModel                       │
    │  │   "internvl3_vqa"  → VQABase  ※ cvEvent인데 VQABase 파싱  │
    │  │                                                            │
    │  │ retEvent 파싱: 전부 → RetrievalBase (공통)                 │
    │  │ vqaEvent 파싱: 전부 → VQABase (공통)                       │
    │  └─────────────────────────────────────────────────────────────┘
    │
    ▼
파싱된 user_params → 각 Service에 전달
```

### 2.2 프레임 처리 단계: Queue → 추론 쓰레드

```
RTSP 프레임 수신 (외부 모듈)
    │
    │  analysis_data_queue.put({
    │    "batches":     [frame1, frame2, ...],     # np.ndarray 리스트
    │    "stream_ids":  ["cam1", "cam2", ...],     # 카메라 ID 리스트
    │    "user_params": [param1, param2, ...]      # 파싱된 파라미터
    │  })
    │
    ▼
ServiceBase.thread_ai_inference() [데몬 쓰레드, while True 루프]
    │
    │  1. Queue에서 배치 데이터 수신
    │  2. _detect(**datas) 호출
    │  3. 결과가 있으면 send_alarm() 호출
    │
    ▼
_detect() 내부 처리 흐름 (모듈별 구현)
    │
    │  ┌─────────────────────────────────────────────┐
    │  │ a. ROI 크롭 (roi_manager)                   │
    │  │ b. 전처리 (Letterbox, 정규화)                │
    │  │ c. 모델 추론 (ONNX / TensorRT)              │
    │  │ d. 후처리 (NMS, threshold 필터링)            │
    │  │ e. 이벤트 판정 (event_manager.update())      │
    │  └─────────────────────────────────────────────┘
    │
    ▼
반환값: { alarms, batches, stream_ids, user_params, is_needed_cvt_color }
```

### 2.3 이벤트 판정 단계: 상태 머신

이벤트 매니저는 프레임 단위 감지 결과를 **4-상태 FSM(Finite State Machine)** 으로 관리하여, 상태 전이가 발생하는 순간에만 알람을 생성합니다.

```
상태 전이 다이어그램:

                  이상 감지
         ┌──────────────────────┐
         │                      ▼
    ┌─────────┐  이상 감지  ┌─────────┐  이상 감지  ┌──────────┐
    │ no_event│ ─────────→ │ started │ ─────────→ │ continue │
    │   (0)   │            │   (1)   │            │   (2)    │◀─┐
    └─────────┘            └─────────┘            └──────────┘  │
         ▲                      │                      │        │
         │                      │ 미감지                │ 미감지  │이상 감지
         │                      ▼                      ▼        │
         │                 ┌─────────┐                 ─────────┘
         └──── 미감지 ─────│  ended  │
                           │   (3)   │
                           └─────────┘

    ★ 알람 발생 지점:
      - no_event → started  : 시작 알람 (isStart: True)
      - continue → ended    : 종료 알람 (isStart: False)
      - started  → ended    : 종료 알람 (isStart: False)
```

```
시간 흐름 예시:

시간 →  t1     t2     t3     t4     t5     t6     t7     t8
감지    미감지  감지    감지    감지    미감지  미감지  감지    감지

상태    0 ───→ 1 ───→ 2 ───→ 2 ───→ 3 ───→ 0 ───→ 1 ───→ 2
               │                     │              │
               ▼                     ▼              ▼
          ★ 시작 알람           ★ 종료 알람    ★ 시작 알람
          (True + UUID)        (False + UUID)  (True + UUID)
```

### 2.4 출력 단계: 알람 전송

```
send_alarm()
    │
    │  1. get_alarm_with_uuid()
    │     - 시작/종료 알람을 UUID로 페어링
    │     - deque 기반 FIFO 매칭
    │
    ▼
output_handler.py → match_outputs()
    │
    ├─── PROD 환경 (ENV=prod) ──────────────────────────────────────────┐
    │                                                                    │
    │    ┌─ RabbitMQ 메시지 전송 ─────────────────────────────────────┐  │
    │    │  alarm_producer.result_queue.put() 호출                    │  │
    │    │                                                            │  │
    │    │  메시지 내용:                                               │  │
    │    │  {                                                          │  │
    │    │    "cameraId": 1,                                           │  │
    │    │    "type": "cvEvent",                                       │  │
    │    │    "organization": "customer_name",                         │  │
    │    │    "name": "entrance_roi",                                  │  │
    │    │    "isStart": true,                                         │  │
    │    │    "thumbnail": <np.ndarray or None>,                       │  │
    │    │    "uuid": "abc-123-...",                                    │  │
    │    │    "incidentThresholdSecond": 5,                             │  │

    │    │  → Queue별 라우팅:                                         │  │

    │    │    retEvent → ret_queue                                    │  │
    │    │    vqaEvent → vqa_queue                                    │  │
    │    │                                                            │  │
    │    │  ※ 썸네일 S3 업로드는 RabbitMQProducer 내부에서 처리       │  │
    │    │    (pia 패키지 쪽 책임)                                    │  │
    │    └────────────────────────────────────────────────────────────┘  │
    │                                                                    │
    ├─── DEV 환경 (ENV=dev) ────────────────────────────────────────────┐
    │    calc_score() 호출 (개발용 검증)                                 │
    └────────────────────────────────────────────────────────────────────┘
```

```

├──────────────┼──────────────────────────────┼──────────────────────────────┤
│ RabbitMQ     │ 알람 메시지 전송              │ Exchange: direct 방식        │

│              │                              │ 설정: utils/init.py          │

│ Redis        │ 로깅 상태 관리                │ get/set "logging" 키         │

```

## 4. 동시성 모델

각 Service 인스턴스는 **2개의 데몬 쓰레드**를 운영합니다.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ ServiceBase 인스턴스                                                         │
│                                                                              │
│  Main Thread (외부)                                                          │
│  └─ RTSP 프레임 수신 → Queue.put()                                           │
│                                                                              │
│  Daemon Thread 1: thread_ai_inference                                        │
│  └─ while thread_state:                                                      │
│       Queue.get() → _detect() → send_alarm()                                │
│                                                                              │
│  Daemon Thread 2: thread_run_get_logging_state                               │
│  └─ while True:                                                              │
│       Redis에서 logging 상태 조회 (1초 주기) → self.logging_flag 갱신         │
│                                                                              │
│  ※ 추론 쓰레드: thread_state=False 또는 종료 신호(all None)로 안전 종료       │
│  ※ 로깅 쓰레드: while True 무한 루프 (데몬이므로 프로세스 종료 시 함께 종료)  │
└──────────────────────────────────────────────────────────────────────────────┘
```
